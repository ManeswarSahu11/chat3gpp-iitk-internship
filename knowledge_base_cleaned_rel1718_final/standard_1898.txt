Title Path: Scope
Content: The present document specifies the protocol aspects for the identity management capability of SEAL to support vertical applications (e.g. V2X) over the 3GPP system. The present document is applicable to the User Equipment (UE) supporting the identity management client functionality as described in 3GPP TS 23.434 , to the application server supporting the identity management server functionality as described in 3GPP TS 23.434 and to the application server supporting the vertical application server (VAL server) functionality as defined in specific vertical application service (VAL service) specifications. NOTE: The specification of the VAL server for a specific VAL service is out of scope of the present document.
Title Path: Definitions of terms and abbreviations > Terms
Content: For the purposes of the present document, the terms given in 3GPP TR 21.905 and the following apply. A term defined in the present document takes precedence over the definition of the same term, if any, in 3GPP TR 21.905 . Authorisation endpoint: A SEAL identity management server protocol endpoint used by the SEAL identity management client to obtain an authorisation grant, as specified in IETF RFC 6749 . SEAL identity management client: An entity that provides the client side functionalities corresponding to the identity management SEAL service. SEAL identity management server: An entity that provides the server side functionalities corresponding to the identity management SEAL service. Token endpoint: A SEAL identity management server protocol endpoint used by the SEAL identity management client to exchange an authorisation grant for an access token, as specified in IETF RFC 6749 for HTTP and IETF RFC 9200 for CoAP. Title Path: General description
Content: Identity management is a SEAL service that provides the identity management related capabilities to one or more vertical applications. The present document enables a SEAL identity management client and a VAL server to communicate with a SEAL identity management server. The SEAL identity management server authenticates the VAL user's identity by verifying the credentials provided by the VAL user. When the VAL user is authenticated it is provided with an access token which is used for accessing different SEAL services.
Title Path: Functional entities > SEAL identity management client (SIM-C)
Content: The SIM-C is a functional entity that acts as the application client for VAL user identity related transactions. To be compliant with the HTTP procedures in the present document the SIM-C shall: support the user authentication procedure specified in clause 6.2.2; and support the token exchange procedure specified in clause 6.2.3. To be compliant with the CoAP procedures in the present document the SIM-C: shall support the role of CoAP client as specified in IETF RFC 7252 ; sh ould support CoAP over TCP and Websocket as specified in IETF RFC 8323 ; shall support IETF RFC 9200 ; shall support OSCORE profile of IETF RFC 9203 ; should support DTLS profile of IETF RFC 9202 ; and shall support the procedures in clause 6.2.2.
Title Path: Functional entities > SEAL identity management server (SIM-S)
Content: The SIM-S is a functional entity that authenticates the VAL user's identity by verifying the credentials provided by the VAL user. To be compliant with the procedures in the present document the SIM-S shall: support the user authentication procedure specified in clause 6.2.2; and support the token exchange procedure specified in clause 6.2.3. To be compliant with the CoAP procedures in the present document the SIM-S: shall support the role of CoAP server as specified in IETF RFC 7252 ; sh ould support CoAP over TCP and Websocket as specified in IETF RFC 8323 ; shall support IETF RFC 9200 ; shall support OSCORE profile of IETF RFC 9203 ; should support DTLS profile of IETF RFC 9202 ; and shall support the procedures in clause 6.2.2.
Title Path: Identity management procedures > On-network procedures > User authentication procedure > SIM-C procedure > HTTP based procedure
Content: Upon receiving a request from VAL user to initiate authentication for VAL services, the SIM-C shall: [ a) ] establish a TLS tunnel to the authorisation endpoint of the SIM-S as specified in 3GPP TS 33.434 using the URL of authorisation endpoint of the SIM-S as provided by the specific VAL service; and send an OIDC Authentication Request message as specified in the OpenID Connect 1.0 and IETF RFC 6749 using an HTTP GET request method towards the SIM-S according to IETF RFC 9110 . The SIM-C shall include the following parameters as specified in 3GPP TS 33.434 in the query component of the authorization endpoint's URI using the "application/x-www-form-urlencoded" format as specified in W3C.REC-html401-19991224 : response_type; client_id; scope; redirect_uri; state; acr_values; code_challenge; and code_challenge_method. Upon receiving an HTTP 200 (OK) response from the SIM-S, the SIM-C shall: [ a) ] prompt the VAL service user for their username and password; generate an HTTP POST request method containing the VAL service user's username and password; and send the HTTP POST request method towards the SIM-S. Upon receiving an OIDC Authentication Response message, the SIM-C shall: [ a) ] establish a TLS tunnel to the token endpoint of the SIM-S as specified in 3GPP TS 33.434 ; and send an OIDC Token Request message as specified in OpenID Connect 1.0 and IETF RFC 6749 using an HTTP POST request method towards the SIM-S according to IETF RFC 9110 . The SIM-C shall include the following parameters in the entity body of the HTTP POST request using the "application/x-www-form-urlencoded" format as specified in W3C.REC-html401-19991224 as specified in 3GPP TS 33.434 : grant_type; code; client_id; redirect_uri; and code_verifier. Upon receiving an OIDC Token response message from the SIM-S, the SIM-C shall: [ a) ] validate the id_token, access_token and refresh token in the received OIDC Token Response message as specified in the OpenID Connect 1.0 specification; and provide the id_token and access_token in the received OIDC Token Response message to the VAL user. The SIM-C may repeat the entire procedure in this clause as needed to obtain the necessary authorisation tokens for the VAL service clients, depending on the scope parameter in the Authentication Request message as specified in 3GPP TS 33.434 .
Title Path: Identity management procedures > On-network procedures > User authentication procedure > SIM-C procedure > CoAP based procedure
Content: Upon receiving a request from VAL user to initiate authentication for VAL services, the SIM-C: [ a) ] may establish a (D)TLS tunnel to the token endpoint of the SIM-S as specified in 3GPP TS 33.434 using the URL of token endpoint of the SIM-S as provided by the specific VAL service; and shall send an ACE-OAUTH Token Request message with client credentials grant type as specified in IETF RFC 9200 using a CoAP POST request towards the SIM-S. The SIM-C shall use the "application/ace+cbor" format and: [ a) ] shall include grant type parameter; shall include scope parameter; may include req_cnf parameter; and may include ace_profile parameter, in the message payload as specified in IETF RFC 9200 . Upon receiving an CoAP 2.01 (Created) response from the SIM-S, the SIM-C shall: [ a) ] validate the access token as specified in IETF RFC 9200 ; and provide the access token in the received ACE-OAUTH Token Response message to the VAL user. The SIM-C may repeat the entire procedure in this clause as needed to obtain the necessary access tokens for the VAL service clients, depending on the scope parameter in the Token Request message as specified in 3GPP TS 33.434 .
Title Path: Identity management procedures > On-network procedures > User authentication procedure > SIM-S procedure > HTTP based procedure
Content: Upon receiving an OIDC Authentication Request message as specified in the OpenID Connect 1.0 and IETF RFC 6749 via a secure TLS tunnel between the SIM-C and the authorisation endpoint of the SIM-S, the SIM-S shall: [ a) ] validate the received OIDC Authentication Request message as specified in the OpenID Connect 1.0 and IETF RFC 6749 ; generate an HTTP 200 (OK) response according to IETF RFC 9110 including form data to prompt the VAL service user for their username and password credentials; and send the HTTP 200 (OK) response towards the SIM-C. Upon receiving an HTTP POST request method from the SIM-C containing the VAL service user's username and password, the SIM-S authenticates the VAL service user and shall: [ a) ] generate an OIDC Authentication Response message as specified in OpenID Connect 1.0 and IETF RFC 6749 with the following clarifications: shall generate an HTTP 302 (FOUND) response according to IETF RFC 9110 ; and shall include the following parameters as specified in 3GPP TS 33.434 : code; and state, in the query component of the redirection URI contained in the Location header field of the HTTP FOUND request method using the "application/x-www-form-urlencoded" format as specified in W3C.REC-html401-19991224 ; and send the HTTP 302 (FOUND) response towards the SIM-C. Upon receiving an OIDC Token Request message via a secure TLS tunnel established between the SIM-C and the token endpoint of the SIM-S, the SIM-S shall: [ a) ] validate the OIDC Token Request message and if valid shall generate an OIDC Token Response message as specified in OpenID Connect 1.0 and IETF RFC 6749 with the following clarifications: shall generate an HTTP 200 (OK) response according to IETF RFC 9110 ; shall based on the received VAL user ID obtained from the received user authentication credentials, determine the VAL service ID of the VAL service user; shall include the: access_token; token_type; and expires_in. parameters and may include the: id_token; and refresh_token. parameters as specified in 3GPP TS 33.434 ; and shall include the other required parameters as specified in OpenID Connect 1.0 and IETF RFC 6749 ; and shall send the HTTP 200 (OK) response towards the SIM-C.
Title Path: Identity management procedures > On-network procedures > User authentication procedure > SIM-S procedure > CoAP based procedure
Content: Upon receiving an ACE-OAUTH Token Request message with client credentials grant type as specified in IETF RFC 9200 optionally via a secure (D)TLS tunnel between the SIM-C and the token endpoint of the SIM-S, the SIM-S shall: [ a) ] validate the ACE-OAuth Token Request message and if valid shall generate an ACE-OAuth Token Response message as specified in IETF RFC 9200 with the following clarifications: shall generate an COAP 2.01 (Created) response according to IETF RFC 9200 ; based on the received client credentials, shall determine the VAL user ID, VAL service ID of the VAL service user; shall include parameters: access_token; expires_in; ace_profile; and rs_cnf; and shall include the other required parameters as specified in IETF RFC 9200 ; and shall send the CoAP 2.01 (Created) response towards the SIM-C.
Title Path: Identity management procedures > On-network procedures > Token exchange procedure > SIM-C procedure
Content: Upon receiving a request from the VAL user to acquire a security token for authentication of the VAL services, the SIM-C shall: [ a) ] establish a TLS tunnel to the token endpoint of the SIM-S; and send a Token Exchange Request message as specified in 3GPP TS 33.434 and IETF RFC 8693 using an HTTP POST request method towards the SIM-S according to IETF RFC 9110 . The following parameters shall be included in the entity body of the HTTP POST request using the "application/x-www-form-urlencoded" format as specified in W3C.REC-html401-19991224 : grant_type; code; client_id; redirect_uri; and code_verifier. Upon receipt of an HTTP 200 (OK) response from SIM-S, the SIM-C shall extract the security token contained in the access_token parameter of the received Token Exchange Response message as specified in IETF RFC 8693 and send it to the VAL user.
Title Path: Identity management procedures > On-network procedures > Token exchange procedure > SIM-S procedure
Content: Upon receiving a Token Exchange Request message as specified in IETF RFC 8693 via a secure TLS tunnel between the SIM-C and the token endpoint of the SIM-S, the SIM-S shall: [ a) ] validate the received Token Exchange Request message as specified in IETF RFC 8693 ; and send a Token Exchange Response message as specified in IETF RFC 8693 and IETF RFC 6749 using an HTTP 200 (OK) response to the SIM-C according to IETF RFC 9110 . The following parameters shall be included, access_token; token_type; and expires_in. and the following parameters may be included, id_token; and refresh_token. in the HTTP 200 (OK) response and are serialized into a JavaScript Object Notation (JSON) structure as specified in IETF RFC 8693 and IETF RFC 7159 .
