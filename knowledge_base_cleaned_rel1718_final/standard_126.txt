Title Path: Configuration Management procedures > MO configuration procedure
Content: This procedure shows how to configure the attributes of the existing MO corresponding to a VNF instance. Main steps for MO configuration: NM sends a request of configuring the attributes of the existing MO corresponding to a VNF instance to EM, this request includes relevant parameters for the MO configuration. When EM receives the MO configuration request, it configures the attributes of the existing MO. EM responds the result of the MO configuration to NM.
Title Path: Configuration Management procedures > Procedure of updating MOI(s) after a VNF is scaled
Content: This procedure shows how to update corresponding MOI(s) after a VNF is scaled. The procedure can be triggered by NM or EM. Scenario 1: Triggered by NM The use case for scenario 1 is in clause 6.4.5 of . In this case, the main steps of the procedure are: NM receives the message indicating the VNF instance has been scaled from NFVO (refer to step 3 of procedure in clause 4.2.3.3 of TS 28.526 ). NM decides the MOI(s) corresponding to the subject VNF instance need to be updated. NM sends a request to EM to update the MOI(s) corresponding to the subject VNF instance. EM updates the attributes of the MOI(s) corresponding to the subject VNF instance. EM sends the notification to NM about the update of the MOI(s). : The assumption of this scenario is that NM can know the relationship between VNF instance and corresponding MOI(s). NM EM 3. Title Path: Configuration Management procedures > MO creation > MO creation for a specified VNF instance
Content: Operator wants to create MOI(s) corresponding to a specified VNF instance. Operator, via NM, knows the identifier of the specific VNF instance via NM reception of the VNF instance instantiated notification. The figure 4.4.2-1 illustrates the procedure of creating MOI(s) for a specified VNF instance. NM sends a createMO (see clause 7.6.1 in ) to EM to create MOI(s) corresponding to the specified VNF instance with VNF instance identifier included. The other configuration parameters are also included in the request if needed. EM creates the MOI(s) and sets the relevant MOI(s) attribute with the VNF Instance identifier referring to the specified VNF instance. EM may configure other attributes of the created MOI(s) if needed. EM sends a notifyObjectCreation to NM to indicate the result of the MO creation to NM.
Title Path: Configuration Management procedures > VNF termination triggers MO attribute value change
Content: This procedure shows the action of EM when it receives the VNF lifecycle change notification indicating a VNF instance has been terminated. It is assumed that a MO has been created to represent a VNF instance, and EM has subscribed to receive the VNF lifecycle change notification from VNFM: VNFM sends a Notify (see clause 7.3.3 ), carrying VnfLifecycleChangeNotification to EM (see clause 9.5.2 ) to indicate the result of VNF termination, when the VNF termination operation is completed. EM detects that a VNF instance has been terminated by checking the attributes status = "result" and operation = "termination", and decides to modify the MO attribute to remove the association with the VNF instance identified by vnfInstanceId. 3) EM sends a notifyAttributeValueChange to NM to indicate the MO attribute value has been changed.
