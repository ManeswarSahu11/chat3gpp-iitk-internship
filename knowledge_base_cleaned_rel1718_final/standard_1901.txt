Title Path: Scope
Content: The present document contains the coding of information necessary for support of supplementary service operation on the mobile radio interface layer 3. Clause 2 gives the functional definitions and contents of messages for call independent supplementary service operations. Messages necessary for support of call related supplementary service operations are defined in TS 24.008. Clause 3 gives the general format and coding for messages used for call independent supplementary service and the format and coding of information elements used for both call related and call independent supplementary service operations. Clause 4 gives the specification of the call related and call independent supplementary service operations.

Title Path: Message functional definitions and contents > General
Content: This clause defines the structure of the messages of the layer 3 protocol defined in TS 24.080. These messages are standard L3 messages as defined in TS 24.007. Each definition includes: [ a) ] a brief description of the message; a table listing the information elements in the order of their appearance in the message. In a sequence of consecutive IEs with half octet length, the first IE occupies bits 1 to 4 of octet N, the second bits 5 to 8 of octet N, the third bits 1 to 4 of octet N+1 etc.. For each IE the table indicates: the information element identifier, in hexadecimal notation, if the IE has format T, TV or TLV. If the IEI has half octet length, it is specified by a notation representing the IEI as a hexadecimal digit followed by a "-" (example: B-); the name of the IE (which gives an idea of the semantics of the element), which is used in this and other specifications as a reference to the IE within the message; the name of the type of the IE (which indicates the coding of the value part of the IE), and a reference to a description of the value part of the IE; the presence requirement indication (M, C or O) for the IE, as defined in TS 24.007; the format of the IE (T, V, TV, LV, TLV) as defined in TS 24.007; the length of the IE (or permissible range of lengths), in octets, in the message, where "?" means that the maximum length of the IE is only constrained by the link layer protocol, and in the case of the facility IE by possible further considerations specified in TS 24.010. This indication is non-normative. Clauses specifying conditions for IEs with presence requirement C or O in the relevant message. Together with other conditions specified in TS 24.080, TS 24.010 or TS 24.08x and 24.09x-series this defines when the IE shall be included or not, what non-presence of such IEs means, and (for IEs with presence requirement C) the static conditions for presence and/or non-presence of the IEs (see TS 24.007).

Title Path: General message format and information elements coding > Overview
Content: Within the layer 3 protocol defined in TS 24.080, every message is a standard L3 message as defined in TS 24.007. This means that the message consists of the following parts: [ a) ] protocol discriminator; transaction identifier; message type; other information elements, as required. Unless specified otherwise, a particular information element may be present only once in a given message. When a field extends over more than one octet, the order of bit values progressively decreases as the octet number increases. The least significant bit of the field is represented by the lowest numbered bit of the highest numbered octet of the field.

Title Path: General message format and information elements coding > Facility information element > Component ID tag
Content: The term Component ID refers to the Invoke ID or the Linked ID. The Component ID tag is coded as shown in table 3.8. The length of a Component ID is 1 octet. An Invoke Component has one or two Component IDs: an Invoke ID, and if it is desired to associate the Invoke with a previous Invoke, then the Linked ID is provided in addition to the Invoke ID. Return Result and Return Error Components have one Component ID, called an Invoke ID which is the reflection of the Invoke ID of the Invoke Component to which they are responding. The Reject Component uses as its Invoke ID, the Invoke ID in the Component being rejected. If this ID is unavailable (e.g. due to mutilation of the message not detected by lower layers), then the Invoke ID tag is replaced with a universal NULL tag as shown in table 3.9. Universal NULL has always length = 0. Any kind of component, except a reject component, may be rejected. If an Invoke containing both Invoke and Linked IDs is being rejected, only the Invoke ID is used in the Reject Component.

Title Path: Supplementary services operation specifications > General
Content: This clause specifies the abstract syntax for the Supplementary Service protocol using the Abstract Syntax Notation One (ASN.1), defined in ITU-T Rec. X.680 and X.681. The mapping of OPERATION and ERROR to components is defined in clause 3 of this specification. The encoding rules which are applicable to the defined abstract syntax are the Basic Encoding Rules for Abstract Syntax Notation One, defined in ITU-T Rec. X.690 with the same exceptions as stated in TS 29.002. For each Supplementary Service parameter which has to be transferred by a Supplementary Service message, there is a PDU field (an ASN.1 NamedType) whose ASN.1 identifier has the same name as the corresponding parameter, except for the differences required by the ASN.1 notation (blanks between words are removed, the first letter of the first word is lower-case and the first letter of the following words are capitalized (e.g. "bearer service" is mapped to "bearerService"). In addition some words may be abbreviated as follows: ms mobile subscriber; ss supplementary services; cug closed user group. The ASN.1 data type which follows the words "ARGUMENT", "PARAMETER" or "RESULT" (for information objects of class "OPERATION" and "ERROR") is always optional from a syntactic point of view. However, except specific mention, it has to be considered as mandatory from a semantic point of view. When in an invoke component, a mandatory element is missing in any component or inner data structure, a reject component is returned with the problem code "Mistyped Parameter". When an optional element is missing in an invoke component or in an inner data structure while it is required by the context, an error component is returned; the associated type of error is "DataMissing". In case an element is defined as mandatory in the protocol description (TS 24.080 including imports from TS 29.002), but is not present according to the service description (stage 1 to stage 3), the ASN.1 protocol description takes precedence over the diagrams in the TS 24.08x and 24.09x-series of technical specifications. When possible operations and errors are imported from TS 29.002 thereby making the MSC transparent to most of the messages sent to or from the MS. Timer values for operations which require timers are shown as ASN.1 comments. The extension marker " " shall be used in the same way as described in TS 29.002 and shall be supported on the radio interface by the MS and the network for all operations defined in this specification including those imported from TS 29.002.

Content: This operation is invoked by an MS to request the network for a supplementary service deactivation. When no BasicService parameter is provided, the deactivation applies to all provisioned and applicable basic services.
Title Path: Supplementary services operation specifications > Operation types > Operations description > interrogateSS (MS -- network)
Content: This operation is invoked by an MS to request the network for a supplementary service interrogation. When no BasicService parameter is provided, the interrogation applies to all provisioned and applicable basic services.
Title Path: Supplementary services operation specifications > Operation types > Operations description > notifySS (network -- MS)
Content: This operation is invoked by the network to forward a supplementary service notification towards a mobile subscriber.
Title Path: Supplementary services operation specifications > Operation types > Operations description > registerPassword (MS -- network)
Content: This operation is invoked by an MS to register a new password related to the management by the subscriber himself of subscription data in the HLR. The operation "Register password" will be successful if the subscriber can provide the old password, the new password and the new password again as results of 3 subsequent operations "Get password".
Title Path: Supplementary services operation specifications > Operation types > Operations description > getPassword (network -- MS)
Content: This operation is invoked by the network to request a password from the mobile subscriber. It may be used to allow the registration of a new password or the management of subscription data by the subscriber himself (e.g. modification of call barring activation status).
Title Path: Supplementary services operation specifications > Operation types > Operations description > processUnstructuredSS-Data (MS -- network)
Content: This operation is invoked by an MS to relay unstructured information in order to allow end to end SS operation between the MS and the network following specific rules (e.g. embedding of keypad commands). The operation is used in order to provide backward compatibility (see TS 24.090).
Title Path: Supplementary services operation specifications > Operation types > Operations description > processUnstructuredSS-Request (MS -- network)
Content: This operation is invoked by an MS to start an unstructured supplementary service data application in the network.
Title Path: Supplementary services operation specifications > Operation types > Operations description > unstructuredSS-Request (network -- MS)
Content: This operation is invoked by the network to request unstructured information from the MS in order to perform an unstructured supplementary service data application.
Title Path: Supplementary services operation specifications > Operation types > Operations description > unstructuredSS-Notify (network -- MS)
Content: This operation is invoked by the network to give an unstructured supplementary service notification to the mobile user.
Title Path: Supplementary services operation specifications > Operation types > Operations description > forwardCheckSSIndication (network -- MS)
Content: This operation is invoked by the network to indicate to the mobile subscriber that the status of supplementary services may not be correct in the network. The procedures for initiating ForwardCheckSSIndication are specified in TS 29.002.

Title Path: Supplementary services operation specifications > Errors > Errors description
Content: For each error this clause provides a brief prose description.
Title Path: Supplementary services operation specifications > Errors > Errors description > unknownSubscriber
Content: This error is returned by the network when it is requested to perform an operation concerning an unknown subscriber.
Title Path: Supplementary services operation specifications > Errors > Errors description > bearerServiceNotProvisioned
Content: This error is returned by the network when it is requested to perform an operation on a supplementary service and not even a subset of the requested bearer service group has been subscribed to.
Title Path: Supplementary services operation specifications > Errors > Errors description > teleServiceNotProvisioned
Content: This error is returned by the network when it is requested to perform an operation on a supplementary service and not even a subset of the requested teleservice group has been subscribed to.
Title Path: Supplementary services operation specifications > Errors > Errors description > illegalSS-Operation
Content: This error is returned by the network when it is requested to perform an illegal operation which is defined as not applicable for the relevant supplementary service(s) (e.g. registration request for a service which must be registered by the administration). For the definition of the allowed operations for the individual supplementary services, see TS 24.08x and 24.09x-series of technical specifications.
Title Path: Supplementary services operation specifications > Errors > Errors description > ss-ErrorStatus
Content: This error is returned by the network when it is requested to perform an operation which is not compatible with the current status of the relevant supplementary service. The current status may be given as additional information by use of the SS-parameter.
Title Path: Supplementary services operation specifications > Errors > Errors description > ss-NotAvailable
Content: This error is returned by the network when it is requested to perform an operation on a supplementary service which is not available in the current location area.
Title Path: Supplementary services operation specifications > Errors > Errors description > ss-SubscriptionViolation
Content: This error is returned by the network when it is requested to perform an operation on a supplementary service, transgressing the subscription restrictions. The nature of the restriction or the transgressed options may be sent as parameters.
Title Path: Supplementary services operation specifications > Errors > Errors description > ss-Incompatibility
Content: This error is returned by the network when it is requested for a supplementary service operation incompatible with the status of an other supplementary service or with the teleservice or bearer service for which the operation is requested. This error shall only be used if the operation is not compatible for even a subset of the teleservice group or bearer service group specified in the request. The identity and status of the conflicting service may also be indicated. The additional information may contain the SS-code parameter, the Basic Service Group parameter and the SS-status parameter.
Title Path: Supplementary services operation specifications > Errors > Errors description > systemFailure
Content: This error is returned by the network, when it cannot perform an operation because of a failure in the network.
Title Path: Supplementary services operation specifications > Errors > Errors description > dataMissing
Content: This error is returned by the network when an optional parameter is missing in an invoke component or an inner data structure, while it is required by the context of the request.
Title Path: Supplementary services operation specifications > Errors > Errors description > unexpectedDataValue
Content: This error is returned by the network when it receives a parameter with an unexpected value, without type violation.
Title Path: Supplementary services operation specifications > Errors > Errors description > passwordRegistrationFailure
Content: This error is returned when a password registration procedure fails because of abnormal subscriber inputs. A more specific diagnostic may be passed as error parameter and indicates situations such as: invalid password format; new passwords mismatch.
Title Path: Supplementary services operation specifications > Errors > Errors description > negativePasswordCheck
Content: This error is returned to indicate the negative result of a password check because the subscriber has not provided the required password or has provided a password which does not match the valid one.
Title Path: Supplementary services operation specifications > Errors > Errors description > facilityNotSupported
Content: This error is returned by the network receiving a request about a facility which is not supported in the PLMN.
Title Path: Supplementary services operation specifications > Errors > Errors description > resourcesNotAvailable
Content: This error is returned by the network to the MS if temporarily there are no resources to support e.g. a multi party call available in the network.
Title Path: Supplementary services operation specifications > Errors > Errors description > maxNumberOfMPTY-ParticipantsExceeded
Content: This error is returned by the network to the MS if the request must be rejected because the number of subscribers to join a multi party call would exceed the maximum value.
Title Path: Supplementary services operation specifications > Errors > Errors description > callBarred
Content: This error is returned by the network to the MS when call independent subscriber control procedures are barred by the operator. The parameter "operator barring" shall be included.
Title Path: Supplementary services operation specifications > Errors > Errors description > numberOfPW-AttemptsViolation
Content: This error is returned by the network to the MS when the maximum number of wrong password attempts is exceeded.
Title Path: Supplementary services operation specifications > Errors > Errors description > absentSubscriber
Content: This error is returned when the subscriber has activated the detach service or the system detects the absence condition. This error is not used on the radio interface but only between network entities.
Title Path: Supplementary services operation specifications > Errors > Errors description > illegalSubscriber
Content: This error is returned when illegality of the access has been established by use of authentication procedure. This error is not used on the radio interface but only between network entities.
Title Path: Supplementary services operation specifications > Errors > Errors description > illegalEquipment
Content: This error is returned when the IMEI check procedure has shown that the IMEI is prohibited listed or not permitted listed. This error is not used on the radio interface but only between network entities.
Title Path: Supplementary services operation specifications > Errors > Errors description > ussd-Busy
Content: This error is returned by the MS to the network when the MS is not able to process the unstructured supplementary service data operation due to an on-going MMI input of the user or an already existing call independent supplementary service transaction.
Title Path: Supplementary services operation specifications > Errors > Errors description > unknownAlphabet
Content: This error is returned by the MS or the network when the alphabet/language used for the unstructured supplementary service data operation is not known by the network or the MS.
Title Path: Supplementary services operation specifications > Errors > Errors description > invalidDeflectedToNumber
Content: This error is returned if the requested deflected-to number is invalid.
Title Path: Supplementary services operation specifications > Errors > Errors description > specialServiceCode
Content: This error is returned if diversion to a special service code was requested.
Title Path: Supplementary services operation specifications > Errors > Errors description > deflectionToServedSubscriber
Content: This error is returned if a diversion to the served subscriber's number was requested.
Title Path: Supplementary services operation specifications > Errors > Errors description > rejectedByNetwork
Content: This error is returned by the network when the network rejects User-to-User Signalling service request.
Title Path: Supplementary services operation specifications > Errors > Errors description > rejectedByUser
Content: This error is returned by the remote party when the remote party rejects User-to-User Signalling service request.
Title Path: Supplementary services operation specifications > Errors > Errors description > positionMethodFailure
Content: This error is returned by the network when the network is unable to obtain any of the location information requested or none of the information obtained satisfies the requested LCS QoS or if requested LCS assistance data could not be transferred or requested deciphering keys for broadcast assistance data could not be returned.
Title Path: Supplementary services operation specifications > Errors > Errors description > resourceLimitation
Content: This error is returned when a requested operation cannot be performed due to insufficient resources.
Title Path: Supplementary services operation specifications > Errors > Errors description > lcs-invalidPru
Content: This error is returned when a requested operation is from a invalid PRU.
Title Path: Supplementary services operation specifications > Errors > Errors description > lcs-PruAssociationRej
Content: This error is returned when a requested operation cannot be accepted by the network, e.g., the target LMF is not the correct serving LMF of the PRU, and the routing ID of a new serving LMF may be returned to the PRU.
