Title Path: Scope
Content: The present document specifies procedures and protocol elements for tunnelling of IMS traffic over restrictive access networks, specifically procedures and protocol elements for establishing, maintaining, and sending traffic via a firewall traversal tunnel between the UE and an enhanced firewall traversal function (EFTF) in the network. The present document is applicable to UE and EFTF. The present document applies only to the case when the IMS traffic is not routed via EPC of a PLMN. Procedures for tunnelling of IMS traffic that is routed via EPC are specified in 3GPP TS 24.302 annex F.

Title Path: UE network protocols > General
Content: In order to access to IMS via restrictive non-3GPP access network, the UE and the EFTF shall establish a firewall traversal tunnel to IP network of IMS (FTT-IMS) using the UE requested FTT-IMS establishment procedure according to subclause 5.2. The UE and the EFTF shall send the IP packets using the IP packet transport FTT-IMS procedure according to subclause 5.3. The UE and the EFTF shall use the IP protocol according to clause 6. When FTT-IMS is no longer needed (e.g. if the UE deregistered from IMS), the UE shall perform the UE requested FTT-IMS release procedure according to subclause 5.4. When FTT-IMS is no longer needed, the EFTF can perform the EFTF requested FTT-IMS release procedure according to subclause 5.5. NOTE: Keep-alive functionality is not defined in this document. Keep-alive functionality defined in 3GPP TS 24.229 can be used to maintain the FTT-IMS between the UE and the EFTF.
Title Path: FTT-IMS protocol > General
Content: The FTT-IMS protocol consists of the UE requested FTT-IMS establishment procedure, the IP packet transport FTT-IMS procedure, the UE requested FTT-IMS release procedure and the EFTF requested FTT-IMS release procedure.
Title Path: FTT-IMS protocol > UE requested FTT-IMS establishment procedure > General
Content: The purpose of the UE requested FTT-IMS establishment procedure is to establish an FTT-IMS between the UE and the EFTF.
Title Path: FTT-IMS protocol > UE requested FTT-IMS establishment procedure > UE procedures > UE requested FTT-IMS establishment procedure initiation
Content: If the UE is not configured with an HTTP proxy address, the UE shall follow the procedures in subclause 5.2.2.2. If the UE is configured with an HTTP proxy address, the UE shall follow the procedures in subclause 5.2.2.3. NOTE: UE configuration of an HTTP proxy address is out of scope of 3GPP.
Title Path: FTT-IMS protocol > UE requested FTT-IMS establishment procedure > UE procedures > UE requested FTT-IMS establishment procedure initiation via restrictive non-3GPP access network type I
Content: In order to establish an FTT-IMS, the UE shall establish a TCP connection to the EFTF address and destination port 443. If the TCP connection establishment is successful, the UE shall establish a TLS connection over the TCP connection according to the TLS profile specified in 3GPP TS 33.310 annex E . If the EFTF address is a FQDN, the UE shall include a TLS extension of type "server_name" in the TLS client hello message according to the TLS profile specified in 3GPP TS 33.310 annex E.
Title Path: FTT-IMS protocol > UE requested FTT-IMS establishment procedure > UE procedures > UE requested FTT-IMS establishment procedure initiation via restrictive non-3GPP access network type II
Content: If the UE is configured with HTTP proxy address, in order to establish an FTT-IMS, the UE shall send HTTP CONNECT request to the HTTP proxy address according to IETF RFC 2817 . The UE shall populate Request-URI of the HTTP CONNECT request with the EFTF address and port 443. Upon receiving HTTP 2xx response to HTTP CONNECT request, the UE shall establish TLS connection according to the TLS profile specified in 3GPP TS 33.310 annex E over the TCP connection used for the HTTP CONNECT request transport. If the EFTF address is a FQDN, the UE shall include a TLS extension of type "server_name" in the TLS client hello message according to the TLS profile specified in 3GPP TS 33.310 annex E.
Title Path: FTT-IMS protocol > UE requested FTT-IMS establishment procedure > UE procedures > UE requested FTT-IMS establishment procedure accepted
Content: When valid TLS Finished message is received over the TCP connection, the UE shall use the connection as the FTT-IMS.
Title Path: FTT-IMS protocol > UE requested FTT-IMS establishment procedure > EFTF procedures
Content: T he EFTF shall handle the TCP connection setup and the TLS connection establishment according to the TLS profile specified in 3GPP TS 33.310 annex E. When TLS Finished message is sent over the TCP connection according to the TLS profile specified in 3GPP TS 33.310 annex E , the EFTF shall use the connection as the FTT-IMS.
Title Path: FTT-IMS protocol > IP packet transport FTT-IMS procedure > General
Content: The purpose of the IP packet transport FTT-IMS procedure is to transport an IPv4 packet or IPv6 packet over an FTT-IMS.
Title Path: FTT-IMS protocol > IP packet transport FTT-IMS procedure > UE procedures > IP packet sending
Content: In order to send an IPv4 packet or IPv6 packet, the UE shall create an IP packet envelope according to subclause 7.1.2.2, and shall populate the IP packet field of the IP packet envelope with the IPv4 packet or the IPv6 packet and shall send the IP packet envelope as TLS application data over the FTT-IMS .
Title Path: FTT-IMS protocol > IP packet transport FTT-IMS procedure > UE procedures > IP packet receiving
Content: Upon receiving the IP packet envelope as TLS application data over the FTT-IMS, the UE shall: if the UE supports IPv4 and the field in the four most significant bits of the first octet of the IP packet field of the IP packet envelope according to subclause 7 .1.2.2 contains 4, handle the IP packet as an IPv4 packet according to IETF RFC 791 ; if the UE supports IPv6 and the field in the four most significant bits of the first octet of the IP packet field of the IP packet envelope according to subclause 7 .1.2.2 contains 6, handle the IP packet as an IPv6 packet according to IETF RFC 2460 ; and if the field in the four most significant bits of the first octet of the IP packet field of the IP packet envelope according to subclause 7.1.2.2 indicates not supported IP version, discard the IP packet envelope. NOTE: The field in the four most significant bits of the first octet of both the IPv4 packet and the IPv6 packet indicates the IP version.
Title Path: FTT-IMS protocol > IP packet transport FTT-IMS procedure > EFTF procedures > IP packet sending
Content: In order to send an IPv4 packet or IPv6 packet, the EFTF shall create an IP packet envelope according to subclause 7.1.2.2, and shall populate the IP packet field of the IP packet envelope with the IPv4 packet or the IPv6 packet and shall send the IP packet envelope as TLS application data over the FTT-IMS .
Title Path: FTT-IMS protocol > IP packet transport FTT-IMS procedure > EFTF procedures > IP packet receiving
Content: Upon receiving the IP packet envelope as TLS application data over the FTT-IMS, the EFTF shall: if the EFTF supports IPv4 and the field in the four most significant bits of the first octet of the IP packet field of the IP packet envelope according to subclause 7.1.2.2 contains 4, handle the IP packet as an IPv4 packet according to IETF RFC 791 ; if the EFTF supports IPv6 and the field in the four most significant bits of the first octet of the IP packet field of the IP packet envelope according to subclause 7.1.2.2 contains 6, handle the IP packet as an IPv6 packet according to IETF RFC 2460 ; and if the field in the four most significant bits of the first octet of the IP packet field of the IP packet envelope according to subclause 7.1.2.2 indicates not supported IP version, discard the IP packet envelope. NOTE: The field in the four most significant bits of the first octet of both the IPv4 packet and the IPv6 packet indicates the IP version.

Title Path: IP roles and IP based procedures > General
Content: This subclause describes IP roles and IP based procedures.
Title Path: IP roles and IP based procedures > IP roles > UE procedures
Content: If IPv4 is supported, the UE shall support acting as host according to IETF RFC 791 . If IPv6 is supported, the UE shall support acting as host according to IETF RFC 2460 .
Title Path: IP roles and IP based procedures > IP roles > EFTF procedures
Content: If IPv4 is supported, the EFTF shall support acting as gateway according to IETF RFC 791 . If IPv6 is supported, the EFTF shall support acting as router according to IETF RFC 2460 .
Title Path: IP roles and IP based procedures > Inner IP address assignment procedure > UE procedures
Content: If the UE has a network interface with a universally administered MAC address, the UE shall use a universally administered MAC address of a network interface of the UE as the UE FTT-IMS MAC address. If the UE does not have a network interface with a universally administered MAC address, the UE shall use a locally administered MAC address where the least significant bit of the last octet is set to zero as the UE FTT-IMS MAC address. If IPv4 is supported, the UE shall support acting as DHCPv4 client according to IETF RFC 2131 . If IPv6 is supported, the UE shall support acting as host supporting the IPv6 stateless address autoconfiguration according to IETF RFC 4862 . Once the FTT-IMS is established, the UE shall: if the UE needs IPv4 connectivity, request IPv4 address using DHCPv4 according to IETF RFC 2131 . The UE shall use the htype, hlen, chaddr according to the UE FTT-IMS MAC address ; and if the UE needs IPv6 connectivity, generate IPv6 address using IPv6 stateless address autoconfiguration according to IETF RFC 4862 . The UE shall create a link-local address according to IETF RFC 4291 using the UE FTT-IMS MAC address. [ NOTE 1:] Further IPv6 configuration can be done using stateless DHCPv6 according to IETF RFC 3736 . [NOTE 2:]DHCPv4 uses IPv4 as transport; IPv6 stateless address autoconfiguration uses IPv6 as transport and DHCPv6 uses IPv6 as transport. Thus, the DHCPv4 messages, IPv6 stateless address autoconfiguration messages and DHCPv6 messages are transported via the FTT-IMS using the IP packet transport FTT-IMS procedure according to subclause 5.3.
Title Path: IP roles and IP based procedures > Inner IP address assignment procedure > EFTF procedures
Content: If IPv4 is supported, the EFTF shall support acting as DHCPv4 server according to IETF RFC 2131 . When acting as DHCPv4 server, the EFTF shall handle each existing FTT-IMS as a different subnet. If the EFTF has a network interface with a universally administered MAC address, the EFTF shall use a universally administered MAC address of a network interface of the EFTF as the EFTF FTT-IMS MAC address. If the EFTF does not have a network interface with a universally administered MAC address, the EFTF shall use a locally administered MAC address where the least significant bit of the last octet is set to one as the EFTF FTT-IMS MAC address. If IPv6 is supported, the EFTF shall support acting as router supporting the IPv6 stateless address autoconfiguration according to IETF RFC 4862 . The EFTF shall create a link-local address according to IETF RFC 4291 using the EFTF FTT-IMS MAC address.
