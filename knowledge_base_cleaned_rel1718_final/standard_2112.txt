Title Path: Scope.
Content: The present document describes the overall architecture of the interface for the provision of MBMS in the E-UTRAN. This includes also a description of the general aspects, assumptions and principles guiding the architecture and interface. The MBMS functions to be provided within that architecture are summarized. It provides an introduction to the TSG RAN TS 36.44x series of UMTS Technical Specifications that define the different interfaces introduced for MBMS provision in E-UTRAN.

Title Path: General Architecture for EUTRAN MBMS
Content: Figure 4-1 shows a simplified architecture for MBMS in LTE/SAE. It consists of EPC functional entities and E-UTRAN nodes. Functions of MBMS EPC entities are defined in TS 23.246 . Functions of MBMS E-UTRAN nodes are defined in TS 36.300 . It should be noted that TS 36.300 also allows MCE be deployed inside eNodeB. Interfaces related to E-UTRAN (i.e. M1, M2 and M3) are introduced in this document. For MBMS, control signaling and user plane data packet are distributed from the EPC to E-UTRAN through different interfaces. Control plane interfaces M3, M2 interface are pure control plane interfaces. M3 between MME and MCE mainly carries MBMS session management signaling. A MCE is connected to one or more than one eNBs within the same MBSFN through M2 interface mainly for MBMS session management signaling and radio configuration signaling. User plane interface M1 interface is a pure user plane interface. A MBMS GW is connected to multiple eNBs through M1 interface for data distribution. Reference points within EPC are not in the scope of this document. Please refer to TS 23.246 for details.
Title Path: Functions of M1 interface for MBMS > General
Content: ``M1'' Interface: MBMS GW eNB The M1 interface is the user plane interface of MBMS between MBMS GW and eNB. IP multicast is used to deliver the downlink packets over the M1 interface and there is no uplink data over M1 radio network layer. SYNC protocol (TS 25.446 ) is used over the M1 interface to keep the content synchronization for MBMS service data transmission.
Title Path: Functions of M1 interface for MBMS > Multicast group management function
Content: IP multicast is used to deliver the packets over the M1 interface. The M1 interface has the function to manage the IP multicast groups. The MBMS GW maintains the IP multicast groups. The MBMS GW allocates the IP multicast group address when the session arrives, and may release it at session stop. At the eNB side, the eNB joins the IP multicast group to receive the MBMS User Plane data at session start, leaves the IP multicast group when the session stops, may leave the IP multicast group when the session suspends and may rejoin the IP multicast group when the session resumes.
Title Path: Functions of M1 interface for MBMS > Content synchronization function
Content: The packets delivered over M1 interface will be synchronously transmitted by eNBs. To support the inter-eNB content synchronization, SYNC protocol layer is defined between BM-SC to eNB, which is used to carry additional information that enable eNBs to identify the timing for radio frame transmission and detect packet loss. Every packet in M1 contains the SYNC protocol information which is encapsulated at BM-SC.
Title Path: Functions of M2 interface for MBMS > General
Content: ``M2'' Interface: MCE eNB An Application Part (M2AP) is defined in TS 36.443 for this interface, which conveys at least radio configuration data for the multi-cell transmission mode eNBs and Session Control Signaling. SCTP (IETF RFC 4960 ) is used as signaling transport i.e. Point-to-Point signaling is applied.
Title Path: Functions of M2 interface for MBMS > M2 interface setup and configuration update functions
Content: The M2 Setup (respectively the eNB and MCE configuration update) function allows to exchange (respectively update) application level data needed for the eNB and MCE to interoperate correctly on the M2 interface after the TNL association has become operational.
Title Path: Functions of M2 interface for MBMS > MBMS Session management function
Content: MBMS session management function is responsible for starting, updating, and stopping MBMS sessions.
Title Path: Functions of M2 interface for MBMS > MBMS Session management function > M2 service context management function
Content: The M2 service context management function supports the establishment of the necessary overall initial service context including MBMS E-RAB context, M2 signalling connection ID(s), etc. The establishment of the overall initial M2 service context is initiated by the MCE. The M2 service context management function also supports the release of the context previously established in the eNB due to service termination. The release of the context is triggered by the MCE.
Title Path: Functions of M2 interface for MBMS > MBMS Session management function > MBMS E-RAB management functions
Content: The MBMS E-RAB service management function is responsible for establishing and releasing E-UTRAN resources for service data transport. The establishment of E-UTRAN resources is triggered by the MCE. The release of E-UTRAN resources is triggered by the MCE.
Title Path: Functions of M2 interface for MBMS > MBMS Session management function > M2 link management function
Content: The M2 signalling link management function provides a reliable transfer of the radio network signalling between eNBs and MCE. The SCTP is used to support the exchange of M2 Application Protocol (M2AP) signalling messages between eNBs and MCE.
Title Path: Functions of M2 interface for MBMS > MBMS Session management function > MBMS Service Suspension and Resumption function
Content: The MBMS Service Suspension function allows the MCE to request the eNB to stop the MBSFN transmission of an ongoing service and release associated RAN resouces while keeping the MBMS context in the eNB. The MBMS Service Resumption function allows to resume a previously suspended MBMS Session.
Title Path: Functions of M2 interface for MBMS > MBMS Scheduling Information transfer function
Content: This function provides multiplexing information if more than one MBMS service is active. The MCE allocates the amount of resources to multiplexed services, using service related information. The eNBs accept the MBMS Scheduling information to synchronize the MCCH transmission in the MBSFN area.
Title Path: Functions of M2 interface for MBMS > MBMS signalling synchronization over M2
Content: The M2 interface shall support timing and synchronization management functions. MCE transmits the control information to eNBs through M2 interface. Synchronization function guarantees the corresponding MCCH to be transmitted at all eNBs simultaneously.
Title Path: Functions of M2 interface for MBMS > M2 interface reset and error processing function
Content: These functions allow for managing of signalling associations between eNB-MCE, surveying M2 interface and recovering from errors.
Title Path: Functions of M2 interface for MBMS > M2 interface reset and error processing function > Error indication
Content: This function allows the reporting of general error situations on signalling exchange.
Title Path: Functions of M2 interface for MBMS > M2 interface reset and error processing function > Reset
Content: The reset function is used to initialize the peer entity after node setup or after a failure event occurred. The reset function may also be used to initialize part of the peer entity. This procedure can be used by both the eNB and MCE.
Title Path: Functions of M2 interface for MBMS > MBMS Counting Function
Content: The MBMS Counting function allows the MCE to request the eNB(s) to count and report per MBSFN area for one or more MBMS services the number of connected UEs receiving the MBMS Service or interested in receiving it.
Title Path: Functions of M3 interface for MBMS > General
Content: ``M3'' Interface: MME MCE M3 provides the signalling service between MCE and MME that is required to fulfil the M3AP functions listed in TS 36.444 . SCTP (IETF RFC 4960 ) is used as signaling transport i.e. Point-to-Point signaling is applied.
Title Path: Functions of M3 interface for MBMS > MBMS Session management function
Content: MBMS session management function is responsible for starting, updating, and stopping MBMS sessions.
Title Path: Functions of M3 interface for MBMS > MBMS Session management function > M3 service context management function
Content: The M3 service context management function supports the establishment of the necessary E-MBMS service context including E-MBMS E-RAB context, M3 signalling connection ID(s), etc. The establishment of the M3 service context is initiated by the MME. The M3 service context management function also supports the release of the context previously established in the MCE due to service termination. The release of the M3 context is triggered by the MME.
Title Path: Functions of M3 interface for MBMS > MBMS Session management function > MBMS E-RAB management functions
Content: The E-MBMS E-RAB service management function is responsible for establishing and releasing E-UTRAN resources for E-MBMS services. The establishment of E-UTRAN resources is triggered by the MME and requires respective QoS information to be provided to the MCE. The release of E-UTRAN resources is triggered by the MME.
Title Path: Functions of M3 interface for MBMS > M3 interface reset and error processing function
Content: These functions allow for managing of signalling associations between MME-MCE, surveying M3 interface and recovering from errors.
Title Path: Functions of M3 interface for MBMS > M3 interface reset and error processing function > Error indication
Content: The error indication function is used by the MCE (respectively the MME) to indicate to the MME (respectively the MCE) that a logical error has occurred.
Title Path: Functions of M3 interface for MBMS > M3 interface reset and error processing function > Reset
Content: The reset function is used to initialize the peer entity after node setup or after a failure event occurred. The reset function may also be used to initialize part of the peer entity. This procedure can be used by both the MCE and MME.
Title Path: Functions of M3 interface for MBMS > M3 interface setup and configuration update functions
Content: In distributed MCE architecture, the M3 Setup and MCE Configuration Update functions may be used to exchange (respectively update) application level data used for the operation of the M3 interface after the TNL association has become operational.
Title Path: Protocol structure for MBMS related interface in E-UTRAN > General
Content: MBMS related E-UTRAN interfaces, M1, M2 and M3, are layered into a Radio Network Layer (RNL) and a Transport Network Layer (TNL) . The radio network signalling over M3 consists of the M3 Application Protocol (M3AP). The M3AP protocol (TS 36.444 ) consists of procedures between the EPC and E-UTRAN for MBMS. The radio network signalling over M2 consists of the M2 Application Protocol (M2AP). The M2AP protocol (TS 36.443 ) consists of procedures between the MCE and eNB for MBMS.
Title Path: Protocol structure for MBMS related interface in E-UTRAN > M1
Content: The protocol stack structure for M1 interface is defined in TS 36.445 section 5.1 . MBMS user data is distributed from the MBMS GW to eNBs by using IP multicast through the M1 interface. An eNB joins the IP multicast address allocated by MBMS GW during the MBMS Session Start procedure (TS 23.246 ).
