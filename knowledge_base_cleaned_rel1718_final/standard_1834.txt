Title Path: Descriptions > Messages and their contents
Content: This clause contains the detailed description of the information flows used by Multicall. Each Information Element, IE, is marked as (M) Mandatory, (C) Conditional or (O) Optional. A mandatory information element shall always be present. A conditional information shall be present if certain conditions are fulfilled; if those conditions are not fulfilled it shall be absent. An optional information element may be present or absent, at the discretion of the application at the sending entity. This categorisation is a functional classification, i.e., stage 2 information and not a stage 3 classification to be used for the protocol. The stage 2 and stage 3 message and information element names are not necessarily identical.
Title Path: Descriptions > Messages and their contents > Messages between MS and MSC
Content: Table 1 indicates messages between the MS and the MSC for mobile originating calls and mobile terminating calls. (Refer to TS 24.008). The MS shall indicate the maximum number of bearers supported by the MS in the CC capabilities IE. The MS shall also indicate the maximum number of simultaneous speech bearers supported by the MS for future compatibility. For Release 99, the maximum number of simultaneous speech bearers is 1. If the MS does not indicate the maximum number of bearers the network shall assume it does not support Multicall. The network supporting Multicall shall indicate the capability in the NW CC capabilities IE. If the NW CC capabilities IE is not sent from the network, the MS supporting Multicall shall assume that the network doesn't support Multicall. If an MS initiating an emergency call is located in a network that does not support Multicall, the MS shall release one or more existing call to ensure that the emergency call can be established.

Title Path: Interaction with telecommunication services > Speech
Content: The Multicall supplementary service does not provide multiple traffic channels for speech calls. Refer to Procedure Check_OG_Multicall_MSC and Procedure Check_MT_Multicall_MSC. If N _UE is greater than N _SN, the mobile station may initiate an Emergency call even if N _SN has been reached. When the network receives an Emergency call Setup message from the mobile station: if N _SN has not been reached, the network shall accept it regardless of N _SB or N _User; if N _SN has been reached, the network shall reject the emergency call setup attempt. The MS shall release one or more existing calls and it shall re-initiate an Emergency call. The MS shall ensure that an emergency call Setup request is acceptable to a serving network which does not support multicall, if necessary by releasing one or more existing calls.
Title Path: Interaction with telecommunication services > Facsimile service
Content: The Multicall supplementary service provides multiple traffic channels for facsimile service except for alternate speech and facsimile group 3.

Title Path: Interaction with other supplementary services > Call forward on busy (CFB)
Content: The condition NDUB occurs in accordance with the definition for multicall. (See TS 22.135).
Title Path: Interaction with other supplementary services > Call Waiting (CW)
Content: Call Waiting SS will be invoked under the conditions described in TS 22.135.
Title Path: Interaction with other supplementary services > Completion of calls to busy subscriber (CCBS)
Content: The NDUB condition occurs in accordance with the definition for multicall. (See 3GPP TS 22.135). A subscriber provisioned with multicall is in the idle state when the subscriber has no ongoing (active or held) calls. CCBS requests in the destination B CCBS queue shall be processed if destination B is idle.

Content: Figure 14 shows the successful cases of transition between the applicable logical states of Multicall. The state changes are caused by actions of the service provider. Title Path: Transfer of information from HLR to VLR
Content: If the provisioning state for Multicall is "Provisioned" then when the subscriber registers on a VLR the HLR shall send that VLR information about the logical state of Multicall, N _User and N _SB. If the logical state of Multicall, the subscription options N _SB or N _User are changed while a subscriber is registered on a VLR then the HLR shall inform the VLR of the new logical state of Multicall, the new N _User or the new N _SB.
Title Path: Information stored in VLR
Content: The VLR shall store the service state information, N _SB and N _User as received from the HLR.
Title Path: Handover
Content: In the case that the network supports Multicall, it shall be possible to handover multiple bearers (See TS 23.009).
