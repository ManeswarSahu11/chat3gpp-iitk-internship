Title Path: Scope
Content: The present document specifies message bodies for MMS that include different media types, formats and codecs within the 3GPP system. The scope of the present document extends to codecs for speech, audio, video, still images, bitmap graphics, 3D scenes and assets , and other media in general, as well as scene description, multimedia integration and synchronization schemes.

Title Path: Media Types > Speech
Content: NOTE: when Speech is supported, the following requirements imply support for narrow-band, wideband and super wideband operations, in alignment with MTSI TS 26.114 . If Speech is supported, the AMR codec shall be supported for narrow-band speech . The AMR wideband speech codec shall be supported for wideband speech working at 16 kHz sampling frequency. When using speech media type alone, AMR or AMR-WB data is stored according to the file format specified in and EVS data is stored according to the storage specified in Clause A.2.6 of TS 26.445 . If Speech is supported, then EVS decoding capability shall be supported as defined in 3GPP TS 26.117 clause 5.2; and the EVS encoding capabilities as defined in clause 5.3 of TS 26.117 and the sender requirements in clause 6.2.4.3 of TS 26.117 shall be supported. Multi-channel sessions shall not be used when using AMR, AMR-WB and EVS codecs. If Speech is supported, then IVAS decoding capability should be supported as defined in 3GPP TS 26.117 clause 5.2; and the IVAS encoding capabilities as defined in clause 5.3 of TS 26.117 and the sender requirements in clause 6.3.5.3 of TS 26.117 should be supported. NOTE: IVAS codec level setting is TBD.
Title Path: Media Types > Audio
Content: If Audio is supported, then eAAC+ decoding capability shall be supported as defined in 3GPP TS 26.117 clause 5.2 and eAAC+ encoding capability shall be supported as defined in 3GPP TS 26.117 clause 5.3 and the sender requirements in clause 6.3.2.3 of TS 26.117. If Audio is supported, then xHE-AAC stereo decoding capability should be supported as defined in 3GPP TS 26.117 clause 5.2; and the xHE-AAC stereo encoding capabilities as defined in clause 5.3 of TS 26.117 and the sender requirements in clause 6.4.2.3 of TS 26.117 should be supported. NOTE: xHE-AAC is a registered trademark of Fraunhofer in Germany and other countries and is used with Fraunhofer’s permission. If Audio is supported, then IVAS decoding capability should be supported as defined in 3GPP TS 26.117 clause 5.2; and the IVAS encoding capabilities as defined in clause 5.3 of TS 26.117 and the sender requirements in clause 6.3.5.3 of TS 26.117 should be supported. NOTE: IVAS codec level setting is TBD.
Title Path: Media Types > Synthetic audio
Content: If synthetic audio is supported, the Scalable Polyphony MIDI (SP-MIDI) content format defined in Scalable Polyphony MIDI Specification and the device requirements defined in Scalable Polyphony MIDI Device 5-to-24 Note Profile for 3GPP may be supported. SP-MIDI content is delivered in the structure specified in Standard MIDI Files 1.0 , either in format 0 or format 1. In addition the Mobile DLS instrument format defined in and the Mobile XMF content format defined in may be supported. An MMS client supporting Mobile DLS may meet the minimum device requirements defined in in section 1.3 and the requirements for the common part of the synthesizer voice as defined in in sections 1.2.1.2. If Mobile DLS is supported, wavetables encoded with the G.711 A-law codec (wFormatTag value 0x0006, as defined in ) may also be supported. The optional group of processing blocks as defined in may be supported. Mobile DLS resources are delivered either in the file format defined in , or within Mobile XMF as defined in . For Mobile DLS files delivered outside of Mobile XMF, the loading application should unload Mobile DLS instruments so that the sound bank required by the SP-MIDI profile is not persistently altered by temporary loadings of Mobile DLS files. Content that pairs Mobile DLS and SP-MIDI resources is delivered in the structure specified in Mobile XMF . As defined in , a Mobile XMF file shall contain one SP-MIDI SMF file and no more than one Mobile DLS file. MMS clients supporting Mobile XMF must not support any other resource types in the Mobile XMF file. Media handling behaviours for the SP-MIDI SMF and Mobile DLS resources contained within Mobile XMF are defined in .
Title Path: Media Types > Still Image and Bitmap graphics
Content: If still images are supported, ISO/IEC JPEG together with JFIF shall be supported. The support for ISO/IEC JPEG only apply to the following two modes: mandatory: baseline DCT, non-differential, Huffman coding, as defined in table B.1, symbol 'SOF0' in ; optional: progressive DCT, non-differential, Huffman coding, as defined in table B.1, symbol 'SOF2' . For JPEG baseline DCT, EXIF compressed image file format should also be supported, as defined in . In that case there is no requirement for the MMS client to interpret or present the EXIF parameters recorded in the file. If still images are supported, HEIF should be supported which consists in conforming to: the 'heic' brand as defined in ISO/IEC 23008-12 , the 'MiHB' brand as defined in ISO/IEC 23000-22:2019 , and the contained elementary bitstream conforming to H.265 (HEVC) Main Profile, Main Tier, Level 5.1 bitstreams have general_progressive_source_flag equal to 1, general interlaced_source_flag equal to 0, general_non_packed_constraint_flag equal to 1, and general_frame_only_constraint_flag equal to 1. signalled with image/heic, profile="heic,MiHB" itemTypes="hvc1.1.2.L153.B0" or an equivalently compatible media type as defined in . If bitmap graphics is supported, the following bitmap graphics formats should be supported: GIF87a ; GIF89a, ; PNG, .
Title Path: Media Types > Video
Content: If video is supported by the MMS client, the following applies: - Image ratios of 16:9 and 9:16 shall be supported. Other image formats should be supported. the 26143_VIDEO_AVC-HD capability as defined in clause 5.6.1 of TS 26.143 shall be supported and the capability 26143_VIDEO_ENC_AVC-HD as defined in clause 5.6.2 of TS 26.143 may be supported. the 26143_VIDEO_HEVC-HD capability as defined in clause 5.6.1 of TS 26.143 should be supported and the capability 26143_VIDEO_ENC_HEVC-HD as defined in clause 5.6.2 of TS 26.143 may be supported. If the reception of HD-HDR video is supported by the MMS client, then the following applies: the 26143_VIDEO_AVC-FullHD capability as defined in clause 5.6.1 of TS 26.143 shall be supported and the capability 26143_VIDEO_ENC_AVC-FullHD as defined in clause 5.6.2 of TS 26.143 may be supported. the 26143_VIDEO_HEVC-FullHD capability as defined in clause 5.6.1 of TS 26.143 shall be supported and the capability 26143_VIDEO_ENC_HEVC-FullHD as defined in clause 5.6.2 of TS 26.143 shall be supported. the 26143_VIDEO_HEVC-UHD capability as defined in clause 5.6.1 of TS 26.143 should be supported and the capability 26143_VIDEO_ENC_HEVC-UHD as defined in clause 5.6.2 of TS 26.143 may be supported. If stereoscopic 3D video is supported, ITU-T Recommendation H.264 / MPEG-4 (Part 10) AVC Stereo High Profile (SHP) Level 3.1 with frame_mbs_only_flag=1 should be supported. When an H.264 (AVC) SHP sub-bitstream containing the base view only complies with Level 1.3 or below, it should be constrained as follows: the value of the profile_idc should be equal to 66 and the value of the constraint_set1_flag should be equal to 1 in all active sequence parameter sets, i.e. the H.264 (AVC) Constrained Baseline Profile should be indicated to be used for the base view. NOTE: When the base view sub-bitstream of the MM complies with H.264 (AVC) CPB Level 1.3 or below, the base view of an MM can be played back by any MMS (Release 11) client supporting video, or the MM can be modified without re-encoding to an MM including 2D video to be played back in H.264 (AVC) CPB compatible MMS clients. There are no requirements on output timing conformance of H.264 (AVC) decoding (Annex C of ) or H.265 (HEVC) decoding (Annex C of ).

Title Path: Media Types > File Format for video and associated speech/audio media types
Content: To ensure interoperability for the transport of video and associated speech/audio and timed text in an MM, the 3GPP file format with Basic profile shall be supported. The usage of the 3GPP file format shall follow the technical specifications and the implementation guidelines specified in TS 26.233 : For the AMR encoded content, the ISO BMFF track shall conform with the requirements of the codec entry 'samr' as defined in TS 26.244 . For the AMR-WB encoded content, the ISO BMFF track shall conform with the requirements of the codec entry 'sawb' as defined in TS 26.244 . For the EVS encoded content, the ISO BMFF track shall conform with the requirements of the codec entry 'sevs' as defined in TS 26.244 . For the EAAC+ encoded content, the ISO BMFF track shall conform with the requirements of the codec entry 'mp4a.40.5' as defined in TS 26.244 . For the xHE-AAC encoded content, the ISO BMFF track shall conform with the requirements of the codec entry 'mp4a.40.29' as defined in TS 26.244 . For video encoded content, the ISO BMFF track shall conform with the requirements corresponding to the capability as indicated in TS 26.143 clause 5.6. Title Path: Media Types > Media synchronization and presentation format
Content: MMS clients and servers that support HTML shall support the 3GPP HTML5 profile as defined in . MMS servers should support translation from other scene description formats, such as SMIL and XHTML Mobile Profile to HTML5. The MMS client that supports HTML shall include the HTML5 MIME type "text/html" as part of the User Agent header field in the request sent to the server. The MMS Relay/Server shall not accept an MMS message using HTML5 presentation unless it supports HTML5 presentation format. A 3D scene as described in clause 4.15 may be used as the presentation format for the multimedia message. In that case, the glTF 2.0 document or the GLB file shall be carried as the first MIME part of the multi-part MIME message.

Content: If timed text is supported, MMS clients shall support the 26143_TT_3GPP and 26143_ENC_TT_3GPP capabilities as defined in TS 26.143 .

Title Path: Media Types > 3D scenes and assets
Content: If 3D scenes and assets are supported, the 26143_SCENE_GLTF20 capability and the 26143_SCENE_GLTF20_GLB capability as defined in clause 5.8 of TS 26.143 shall be supported assuming either a single body part or a multipart/related body part as defined in clause 3A. If 3D AR scenes and assets are supported, the 26143_SCENE_GLTF20_AR and the 26143_SCENE_GLTF20_GLB_AR capability as defined in clause 5.8 of TS 26.143 shall be supported assuming either a single body part or a multipart/related body part as defined in clause 3A.
